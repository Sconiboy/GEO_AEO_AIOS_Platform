# Buyer-Question Validation Panel

## Purpose

Validate the source-first workflow against a small set of real buyer questions before turning the demo page into a data-driven client tool.

## Panel

| Panel ID | Natural buyer question | Buyer intent |
| --- | --- | --- |
| BQ-01 | Who are the best B2B SaaS SEO agencies? | Agency evaluation |
| BQ-02 | Which B2B SaaS SEO agency can help grow organic pipeline? | Outcome evaluation |
| BQ-03 | Who helps SaaS companies show up in AI search results? | Emerging-category evaluation |

The panel uses natural buyer language. The client page shows this language and the resulting evidence map. Internal research operations remain inside the engagement.

## Natural-Answer Recapture Gate

The first natural answer identifies the names and visible URLs that a buyer may encounter. Preserve it as a discovery record. Do not treat it as governed comparative evidence when the query map, source manifest, and frozen ledger did not already exist.

Route each visible URL through candidate review. After the approved query and selected source candidates are frozen, capture the same natural buyer question again. The fresh answer and its approved source trail form the governed panel record.

## Capture Standard

Capture each question on every accessible declared answer surface. Preserve the visible response, date and time, model label, explicit source URLs, and any access blocks. Keep inaccessible surfaces in the operational log; an access block is not a visibility result.

| Required output | Success condition |
| --- | --- |
| Natural-answer artifact | Raw visible response and capture metadata retained. |
| Source trail | Every explicit visible URL extracted exactly. |
| Evidence collection | Each approved URL is opened and verified, or its collection failure is recorded. |
| Source map | Every URL is labeled as client-owned, competitor-owned, independent, community, review, or unknown. |
| Action plan | Each recommendation points to a verified evidence difference and a measurable completion artifact. |

## Stop Conditions

Stop the panel and report the limitation when an answer has no visible sources, the source cannot be retained, the entity relationship cannot be verified, or the evidence base remains too thin for an action plan. The output in these cases is a source map with an evidence gap—not an invented explanation.

## Decision Gate

The panel passes when it produces a reusable client-facing source map for all three questions and a human-reviewed action plan tied to verified evidence. It then becomes the input specification for the data-driven client tool.
